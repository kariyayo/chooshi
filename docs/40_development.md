# 開発ガイド

このドキュメントでは、アプリの開発・動作確認を行うための基本的な手順について説明します。

## 1. 依存関係のインストール

プロジェクトを新しくクローンした直後や、`pubspec.yaml` を更新した場合は、以下のコマンドを実行して必要なパッケージをインストールします。

```bash
flutter pub get
```

## 2. 自動生成コードのビルド

Freezed や JSON Serializable などのモデルを変更した場合は、以下のコマンドを実行してコード（`*.freezed.dart` や `*.g.dart`）を再生成する必要があります。（今回の `tag_store.dart` のようなロジックのみの変更時は不要です）

```bash
# 1回のみ生成する場合
flutter pub run build_runner build --delete-conflicting-outputs

# ファイルの変更を監視して自動で生成し続ける場合
flutter pub run build_runner watch --delete-conflicting-outputs
```

## 3. アプリの起動（動作確認）

シミュレータ（iOS / Android）または実機をPCに接続し、以下のコマンドでアプリを起動します。

```bash
flutter run
```

### 【Tips】CLIからAndroidエミュレータを起動して確認する手順

GUIを開かずにターミナルだけでエミュレータを立ち上げる手軽な方法です。

1. **利用可能なエミュレータ一覧を確認する**
   ```bash
   flutter emulators
   ```
   （出力結果の例：`Pixel_5_API_33` のようなIDが表示されます）

2. **エミュレータを起動する**
   ```bash
   flutter emulators --launch <表示されたID>
   ```

3. **アプリを実行する**
   起動完了を待ってから通常通り `flutter run` を実行すると、立ち上げたエミュレータにアプリがインストールされて起動します。

※ VSCode や Android Studio などのIDEをお使いの場合は、エディタ上のデバッグ機能（F5キーなど）から起動するのが一般的です。

## 4. 修正の反映（Hot Reload / Hot Restart）

`flutter run` で起動中にコード（Dartファイル）を書き換えて保存した場合、ターミナルで以下のキーを入力することで素早く変更を反映できます。

- **`r` (Hot Reload)**: 
  アプリの状態を保持したまま、UIやロジックの変更を即座に反映します。通常のレイアウト調整やロジック修正の場合はこちらを使用します。
- **`R` (Hot Restart)**: 
  アプリの状態（State）をリセットし、最初から起動し直します。今回のような「アプリ起動時に実行されるデータの読み込みロジック（`fetch`等）」を変更した場合や、全体の状態を初期化したい場合はこちらを使用します。

### 今回のタグ重複バグ修正の確認手順

1. `flutter run` でアプリを起動する
2. 画面下部のメニューなどから「Tags」画面（タグ一覧）を開く
3. 今回の修正により、これまでに重複して表示されていた「カジキ」などのタグが1つにまとまっていることを確認する
4. （追加の確認）ホーム画面に戻り、「＋」ボタンから既存のタグと同じ名前（例：「カジキ」）で異なる評価を付けて投稿する
5. 再び「Tags」画面を開き、重複して行が増えることなく、評価の平均値や回数だけが正しく更新されているか確認する

## 5. 終了手順（アプリ / エミュレータ）

開発を終了する際の安全な手順です。

### アプリの終了
`flutter run` を実行しているターミナルで、キーボードの **`q`** を入力します。
（または `Ctrl + C` を入力します）
これにより、アプリのプロセスが安全に終了します。

### エミュレータの終了
起動しているエミュレータのウィンドウにある **閉じるボタン（×）** をクリックして終了するのが最も簡単かつ安全です。
エミュレータを終了しても、元々の Android Studio などを開いている必要はありません。

---

### 【トラブルシューティング】エミュレータが `offline` になった場合
次回起動時などに `adb devices` でエミュレータが `offline` と表示され、`flutter run` ができなくなることがあります。
その場合は以下の復旧手順を試してください。

1. **ADBサーバーの再起動**
   ターミナルで以下のコマンドを実行します。
   ```bash
   adb kill-server
   adb start-server
   ```
2. **エミュレータの完全再起動（Cold Boot / Wipe Data）**
   上記で直らない場合、エミュレータの状態が破損している可能性があります。
   - **Android Studio** を開き、`Device Manager` を表示します。
   - 対象のエミュレータの右側の「︙」メニューから **`Wipe Data`**（データの初期化）を選択します。
   - 続けて **`Cold Boot Now`**（完全再起動）を選択して立ち上げ直します。

## 6. 本番向けビルド (Production Build)

App Store や Google Play などのストアへ提出するため、または実機に本番用としてインストールするためのビルド手順です。

### iOS (App Store 向け)
```bash
# ipaファイルを生成（Xcode経由でApp Store Connectへアップロード可能）
flutter build ipa
```

### Android (Google Play 向け / 実機インストール向け)

Androidの本番ビルド（App Bundle）は、鍵などの機密情報を安全に扱うため **GitHub Actions** を使用してクラウド上でビルドする仕組みになっています。

1. GitHubのページを開き、**「Actions」** タブへ移動します。
2. 左側のメニューから **「Build Android Release」** を選択します。
3. 右側の **「Run workflow」** ボタンを押してビルドを開始します。
4. 数分待ってビルドが成功すると、画面下部の **「Artifacts」** から `release-appbundle.zip` をダウンロードできます。

※ ローカルでテスト用に実機インストール版（APK）を出力したい場合は、以下のコマンドを実行します。
```bash
# 実機へ直接インストールする配布用（APK）
flutter build apk
```

※ iOSの本番ビルドおよびローカルでのAndroidビルドを行うには、事前に各プラットフォームの署名設定（iOSの証明書/Provisioning Profile、AndroidのKeystore）が完了している必要があります。
